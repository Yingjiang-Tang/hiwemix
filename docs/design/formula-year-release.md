## 数据兼容

- 唯一必需迁移：`supabase-migrations/20261103000000_formula_years.sql`。整个脚本包含在一个事务中，可重复执行。
- 历史配方只通过列默认值读取为 `inherit`，不猜测或回填真实年份；不更新现有配方行、ID、更新时间、色母比例或克重。原颜色年份保留。
- 原 `save_formula_with_components` 签名保留，内部旧事务实现改名后由外层先锁颜色再调用。新应用使用 `save_formula_with_years`，完全缺少年份字段的编辑请求保留现值。
- 缩小颜色年份通过延迟约束检查事务最终状态，冲突时列出配方 ID 并整体回滚。旧应用的颜色保存入口同样受保护。
- 同一颜色与配方保存先锁颜色主行；新旧 RPC 均仅允许 `service_role`。应用写接口继续校验管理员身份。
- 切回旧应用时保留新增表、列、函数与约束，不通过删表或移除自定义年份回滚。
