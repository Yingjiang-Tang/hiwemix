# Data Management 修复记录

日期：2026-11-03。对应 [筛查报告](2026-11-03-data-management-audit.md)，基准提交为 `1647618`。

本批修改保留现有业务数据。修复验证阶段没有执行线上新增、更新、删除、Storage 删除、数据回填或数据库迁移。写入与删除测试均在隔离内存夹具中执行。

| 问题 | 实施的修复 |
|---|---|
| B01 管理员进入后台误跳转 | 由现有服务端 admin layout 校验身份，移除会与客户端角色加载竞争的重复跳转 |
| B02 新增重复 ID 覆盖旧记录 | 品牌、文档、文档分类创建使用 INSERT；编辑品牌/文档使用指定 ID 的 UPDATE；冲突返回 409。施工类型禁止写入 |
| B03 上传结果串表单 | 配方与文档上传绑定当前编辑上下文；切换、关闭或新建后忽略旧结果；上传期间阻止保存 |
| B04 配方年份没有持久化 | 移除配方表单中没有数据库字段支持的年份控件；颜色年份继续保留 |
| B05 任意施工类型导致保存失败 | 类型列表设为只读，接口阻止新增/改名/删除；配方仅提供系统支持的类型，历史关联不迁移 |
| B06 配方异常输入 | 校验组件数组、有效百分比、RGB、密度、工序分组；服务端总和精度与表单一致；非法输入返回 400 |
| B07 相同起始年份冲突 | 表单提示重复起始年份，服务端在写入前校验；漏传年份/变体关联数组时拒绝保存，避免意外清空 |
| B08 文档排序被重置 | 编辑表单携带原 sortOrder；服务端更新未传排序时不写入该字段 |
| B09 统计被数据库单次返回上限截断 | 按主键游标分批读取，同一事件集聚合所有统计；读取失败报错；统一为 UTC 自然日并在界面注明 |
| B10 统计旧响应覆盖新范围 | 请求序号保护，只接受当前范围的响应 |
| B11 加载失败显示为空列表 | 依赖数据全部加载成功后开放表单；失败显示明确错误和重试入口，保留内存中已有数据 |
| B12 移动端触摸区域不足 | 管理模块及弹窗/下拉作用域内统一 44px 最小触摸尺寸；去除管理表单中的 JS 视口判断 |
| B13 删除共享图片 | 配方删除/替换不自动删除物理文件；兼容旧客户端清理请求并保留文件 |
| R01 品牌删除级联风险 | 应用层检查关联颜色，有关联时返回 409，阻止直接级联删除 |
| R02 文档分类删除错误不清楚 | 删除前检查文档关联并返回可读的 409；数据库外键冲突也返回关联提示 |
| R03 类型删除留下镜像/历史引用 | 禁止施工类型写入和删除，保留原类型、镜像和历史关系 |

## 数据影响与边界

- 部署代码不会触发批量数据修改。正常保存仍只修改管理员正在编辑的记录；已有配方 variant_id、图片 URL、颜色年份和关联继续传递。
- 配方类型改为只读；无效配方年份控件消失。保存校验更严格，历史上不符合校验的配方仍保留，但再次编辑保存时需要修正非法输入。
- 统计数字可能上升，因为现在读取完整数据；日期统一为 UTC。统计事件原始记录不变。
- 旧图片保留会增加未引用文件的存储占用；本批不自动清理历史文件。
- 品牌删除采用应用层前置检查，没有修改生产数据库原有 CASCADE 外键。检查与删除之间的极端并发插入仍需数据库事务或 RESTRICT 外键进一步保证；隔离 HTTP 夹具不能证明真实 PostgreSQL 的并发行为。本批没有进行数据库层变更。
- 线上真实 PostgreSQL 的写入、事务与外键删除没有执行；本次不以测试替身代替生产数据库端到端验收。
